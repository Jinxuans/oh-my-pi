# OMP 公司模式实施计划

2026-11-19（北京时间）立项基线，基于 OMP 源码 `b279532036313bdbdfe7a60a613e6d73a4ca8b15`。P0 待启动。

本文件记录实施范围、依赖、验收和阶段决策。[实施台账](implementation-tracker.csv)记录每项任务的实时状态和证据。两份文件以任务编号关联。

## 1. 交付目标

在本地 OMP 中创建、保存和切换多家公司。人类担任董事会，CEO 通过 OMP 主对话协调，部门负责人通过持久任务分工，员工复用现有 OMP 子 agent。试点验收走通 **设目标 → CEO 派单 → CTO 拆分 → 员工交付 → QA 打回与复审 → 董事会批准指定动作 → CEO 汇报**。退出重进后，用户仍能看到任务、产物、决定与运行状态。

- **P1 首版**采用本地单用户、现有终端界面、每个 profile 一次只激活一家公司、单 Git 仓试点、同一物理工作区串行写入。OMP 打开期间按需调度。跨部门协作用任务、评论、显式派单和评审请求。交付基础动作审批、审计和会话级费用控制。
- **P2 日用版**交付重试与排查、每任务 Git 工作区、合并协调、收件箱、基础检索、公司用量账本和备份恢复。
- **P3 原案覆盖**交付多项目与目录、即时通信、文档版本与批注、跨工作搜索、细粒度治理和公司预算。
- 独立 Web 后台、多人或跨设备协作、关掉 OMP 后常驻运行、操作系统级强隔离另立范围。

### 必须保持的运行规则

1. 工作项经历待办、执行、待审核、完成或打回。依赖未满足的工作不可认领。负责人可以持续存在，执行占用随每次尝试变化。
2. 认领、创建运行记录和审计事件在短事务内完成。同一工作项最多一个有效运行。完成和释放校验公司、任务与当前 `run_id`；旧运行停止前不得把同一物理工作区交给下一执行者。
3. 收到外部动作回执前中断时，按稳定的业务幂等键查询或对账。重试复用原业务幂等键。结果无法确认时标记待核实并暂停自动重试。
4. 每次运行按身份、项目和任务获取最新资料。跨公司访问、旧执行回写、过期权限和审批脱离目标版本都应拒绝并留下审计。
5. 受控动作由公司服务执行。文件审批通过后改变产物摘要，或动作批准后改变目标和参数，需重新审核或审批。日志记录必要身份、时间、结果和引用，凭证不进入日志。

## 4. 验收矩阵

台账每项任务可引用下列编号。通过证据应包含基线 commit、测试命令或操作步骤、期望和实测结果，以及经过脱敏的日志或产物位置。

| 验收 ID | 场景 | 通过标准与证据 |
|---|---|---|
| V-01 | 受控子 agent 启动与取消 | 使用 mock provider 记录主线程和 worker 的最终工具列表、任务目录、事件和结果。受控工具可调用，未授权工具被拒绝。取消后没有新的受控写入。达到会话费用门槛时，后续请求被拒绝。 |
| V-02 | A/B 公司、同名成员与项目 | 交替进入不同公司，设置、会话、工具、产物与记录归属正确。用另一公司的资源 ID、会话入口或产物引用读写时拒绝。目录消失时禁止执行。 |
| V-03 | 原子认领、阻塞和晚回写 | 两请求同抢仅一个成功。被依赖阻塞的任务不启动。取消或改派后旧结果被拒绝并留下审计。 |
| V-04 | 正常任务与评审打回 | 保存原提交、QA 意见、重交产物和最终审核版本。CEO 重开后能从持久记录汇报。 |
| V-05 | 工作审核与动作审批 | QA 通过后，未审批动作仍被拦截。授权、版本和参数一致时受控动作执行一次，过期、撤权或改参数均拒绝。记录申请、决定和结果。 |
| V-06 | 认领后、文件已写、动作回执前突然退出 | 重启能区分可创建新尝试、保留差异待检查和待核实外部动作。已发生动作不会自动重复，旧执行未停写时工作区仍占用。 |
| V-07 | 普通 OMP 与数据兼容 | 保留现有启动、`task`、`--restore` 行为；公司功能可停用；旧库迁移及备份恢复通过。记录命令、日志和迁移版本。 |
| V-08 | 真实仓库试点与单 agent 对比 | 完成同一验收任务，记录质量、耗时、模型用量和人工介入。试点报告写明适用任务、阻断缺陷及下一阶段优先级。 |
| V-09 | 并行工作区与合并 | 两任务独立交付，冲突不覆盖原变更。工作区仍在写入或产物待审核时，不进行合并或重分配。 |
| V-10 | 收件箱、即时消息与检索 | 离线请求可回查；消息投递失败回到持久记录；提及不触发派单；搜索、附件与运行日志符合公司和项目权限。 |
| V-11 | 多项目、文档与决策 | 正确定位任务项目与目录；批注可追溯到历史版本；提议、批准、拒绝和替代均有记录；检索返回带版本的授权引用。 |
| V-12 | 用量与预算并发 | 重复事件不重复记账；未知用量显式显示；P3 两运行竞争最后额度时，可计量的新请求按预留规则拒绝或放行，并能结算。 |

## 5. 门槛、降级与发布阻断

| 门槛 | 必查事项 | 未通过时的处理 |
|---|---|---|
| G0 | V-01、V-02、V-03、V-06 的最小证明。确认 OMP 适配改动范围、取消边界和后续工期。 | UI 内切换不稳时使用退出重进。worker 工具注入不稳时限于已验证的执行路径。身份、工作区或迟到写入无法隔开时，暂停进入 P1，先修复或重新评估。 |
| G1 | V-01 至 V-08；试点闭环；功能停用和备份检查。 | 越权、重复执行、任务丢失和普通 OMP 回归阻断发布。审批覆盖不到的外部动作保留董事会人工操作，重新验证受控动作范例。 |
| G2 | V-06 至 V-10；V-12 的归集和去重部分。 | 工作区回收或合并不稳时保持同工作区单写。未知费用单列，待对账动作留在人工队列。 |
| G3 | V-09 至 V-12 完整验收，并回归 G1 的安全和兼容场景。 | 通过范围可保留试用，记录未交付项及影响。存在权限、动作重复或数据丢失问题时保持发布阻断。 |

每道门槛在台账对应行记录「通过 / 限范围通过 / 暂停」、批准人、日期、证据和遗留任务编号。限范围通过必须保留受影响的约束和补齐条件。

## 6. 台账维护

1. 启动时将角色映射到具名负责人和验收人，填计划完成日。先认领 P0-01，明确 P0-02、P0-03 并行人选。
2. 状态按「未开始 → 进行中 → 待验收 → 已完成」更新。受阻时填「阻塞」和阻塞原因；恢复后回到「进行中」。取消或拆分任务保留原编号，用备注链接替代编号。
3. 每个任务在开始前确认前置项。结束时补实际完成日和人日，附 PR、commit、测试日志或本地证据相对路径。验收人对照验收矩阵确认后关闭。
4. 每周更新当前状态、阻塞和阶段剩余人日。范围或估算变化同时更新里程碑说明与台账。启动时填具名责任和计划日期，实施中补实际日期和证据。
